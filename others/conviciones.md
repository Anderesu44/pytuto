# Convenciones de nombres

## camelCase

Este estilo comienza con minúscula y cada palabra siguiente inicia con mayúscula, creando una forma fluida y fácil de leer. Se usa mucho en JavaScript, Java y TypeScript para funciones y variables porque visualmente distingue bien las palabras sin usar símbolos.

## PascalCase (o UpperCamelCase)

En este caso todas las palabras empiezan con mayúscula, lo que da una apariencia más formal y estructurada. Es común en clases, componentes y tipos.

## snake_case

Este estilo separa cada palabra con guiones bajos, lo que facilita la lectura en contextos donde se prefieren nombres claros y planos. Python, SQL y Ruby lo usan para funciones y variables.

## SCREAMING_SNAKE_CASE (o UPPER_CASE)

Aquí todas las letras están en mayúsculas y las palabras se separan con guiones bajos, lo que hace que el nombre resalte de inmediato. Se utiliza para constantes porque comunica que el valor no debe cambiar y debe ser fácilmente reconocible en el código.

## kebab-case

Este estilo usa guiones medios para separar palabras, creando nombres muy legibles en entornos donde no se permiten espacios. Es típico en CSS, HTML y URLs porque los guiones funcionan bien en sistemas que interpretan los nombres como cadenas simples.

## dot.case

Las palabras se separan con puntos, lo que genera una estructura jerárquica visual muy clara. Se usa en configuraciones, namespaces y archivos de localización porque permite organizar conceptos como si fueran rutas o categorías.

<hr>

| Estilo                   | Ejemplo        | Uso típico                  |
| ------------------------ | -------------- | --------------------------- |
| **camelCase**            | `miVariable`   | JS/TS variables y funciones |
| **PascalCase**           | `MiClase`      | Clases, componentes, tipos  |
| **snake_case**           | `mi_variable`  | Python, SQL, Ruby           |
| **SCREAMING_SNAKE_CASE** | `MI_CONSTANTE` | Constantes                  |
| **kebab-case**           | `mi-variable`  | CSS, HTML, URLs             |
| **dot.case**             | `mi.variable`  | Config, i18n                |
